# Reporting a security concern

Use this process for concerns about the Markdown Studio skill, its Python
helpers or its workflows. Examples include a helper reading a file outside
the selected repository or document content causing a host to send private
data to an external service.

## Contact the maintainer

1. Open the repository's [Security page](https://github.com/whale-devx/github-markdown-studio-skills/security).
   If **Report a vulnerability** is available, use the private form.
2. If the button is unavailable, [open an issue](https://github.com/whale-devx/github-markdown-studio-skills/issues/new)
   asking “How can I contact the maintainer privately about a security concern?”
   Keep the public issue to that request. Wait for a private channel before
   sharing affected paths, logs or technical details.
3. In private, include the installed commit or version, the affected helper
   or host, what you expected and what happened. A small example with
   invented content helps the maintainer assess the impact. Remove tokens,
   personal paths and private repository content from any attachments.

For a broken link, a translation correction or a formatting issue, use the
regular [issue tracker](https://github.com/whale-devx/github-markdown-studio-skills/issues).
The [verification guide](skills/github-markdown-studio/references/verification.md)
describes the checks performed by the local audit helper.
